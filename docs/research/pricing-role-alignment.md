# Pricing role alignment

Role requirements were reviewed on 2026-09-02 using current U.S. airline and commercial analytics career pages.

## What FareLab demonstrates

| Common analyst expectation | FareLab evidence |
| --- | --- |
| Monitor fares, traffic, capacity, share, and competitors | Route queue, market explorer, fare index, load factor, share movement, and competitor fare history |
| Diagnose performance with SQL and BI tools | Version-controlled SQL marts, data-quality audits, and linked React visual analysis |
| Forecast demand and compare with a baseline | Expanding-window seasonal-naive, ridge, and gradient-boosting backtests |
| Evaluate pricing scenarios and tradeoffs | Bounded fare, capacity, competitor, demand, elasticity, and optional cost inputs |
| Measure uncertainty and model risk | Forward interval coverage, sensitivity ranges, identification rejection, and a model-risk register |
| Communicate an action to leadership | Ranked review actions and a grounded decision brief with evidence, risks, and a next step |
| Use Python and production-style delivery | Reproducible Python pipeline, typed API, tests, evaluation suite, and deployed application |

This scope is credible for an analyst with early-career pricing, revenue management analytics, or commercial analytics responsibilities. The project is strongest when discussed as a public-data decision-support product and as evidence of judgment about model limits.

## What it does not demonstrate

FareLab does not have booking curves, fare classes, origin-and-destination availability, bid prices, displacement cost, ATPCO filing records, ancillary revenue, route accounting cost, customer shopping data, or live competitor feeds. It therefore cannot demonstrate production inventory control, network revenue management optimization, or causal price elasticity.

Those omissions should be stated in interviews. Claiming them would weaken an otherwise credible project.
